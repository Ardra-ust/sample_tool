UST AI Factory Workshop

Self-contained field manual: starter kits, worksheets, factory anatomy, the 12-command spine, every agent and subagent that ships, and how to add a generic agent (Python and Kotlin are worked samples) without breaking orchestration.

Default stack: Java 21 / Spring Boot 3 + Next.js / TypeScript. Catalog lock: 12 primary agents.

1. How to use this book

This is the operator SOP for the workshop package. Read it as a playbook, not as marketing. Every behavior below is taken from the files named in Source index. Where two files disagree, the live command contract wins over a summary table.

If you are a participant

  1. Pick one IDE kit (Cursor, Claude Code, or Copilot).
  2. Copy the kit into a product repo using that kit’s README.
  3. Fill config.yaml from the worksheet — placeholders are a hard stop.
  4. Run the 12-command spine. Stop at every human gate.

If you are extending the stack

  1. Treat Java + Next.js as the shipped default, not the only possible stack.
  2. Prefer a mode + subagent on backend-agent / frontend-agent over a 13th primary.
  3. Update the command contract, rule, skill, stack-conventions.md, scope.yaml, and all three IDE twins together.
Hard rule Never invent business behavior, API fields, DDL columns, UI copy, or error semantics. Cite a source or register ASSUMPTION-<id> / Open DQ. Agents cannot self-approve BRD, sprint plan, or test-package gates.

3. Orchestration model

Every public slash command is a playbook. Humans invoke the command. The orchestrator loads the contract and delegates. Primaries own a domain. Subagents do bounded work and return IO + confidence. Subagents are never slash-command primaries.

Slash command
  → orchestrator-agent          (route, gates, loop max 3, Next command)
    → primary agent             (owns the domain)
      → subagent(s)             (bounded task, structured IO, confidence)
        → artifacts/audit/...   (every public command)
        → harness-updater       (phase-changing commands only)
flowchart LR U[Operator types /command] --> O[orchestrator-agent] O --> R{Required inputs\nand human gates?} R -->|refuse| N[Tell Next command] R -->|ok| P[Primary agent] P --> S[Subagent chain] S --> V[Validate DoD] V -->|pass iteration 1| A[Audit + optional harness] V -->|findings| P V -->|iteration 3 fail| E[Escalate with gaps] A --> N
Loop policy Build/quality commands: Plan → Act → Validate → Refine. Intake/architecture: Plan → Act → Observe → Reflect. Max 3 is a ceiling. If iteration 1 Validate/Observe passes, stop. Do not burn remaining iterations.

10. Hooks, config, scope, evals, scripts

Config (worksheet)

Copy config.yaml.example → config.yaml and replace every <placeholder>. Orchestrator refuses product code while <project-name> remains (rule 01). Minimum bindings:

  • project.name, project.domain
  • modules.api, modules.ui, modules.openapi
  • evals.rule_source (Accepted BRD path after generate-brd)
  • evals.test_commands.api / ui / e2e (kit defaults: Maven, npm test, Playwright)
  • local_stack.* health URLs and start/verify/stop scripts
  • pipeline.eval_fix_command: close-eval-gaps — do not remove

scope.yaml

Mechanical write allowlists. Orchestrator may only write artifacts/audit/**. Implementers must not write docs/test-cases-br-coverage.md or docs/harness/**. When you add Kotlin/Python roots, add them to backend-agent.write and keep UI denied.

Hooks

  • scaffold-from-command.mjs — create sprint/audit folders on known commands (failClosed: false)
  • verify-artifacts.mjs — artifact policy (failClosed: true on commit/push)
  • .githooks/pre-commit → tools/check-artifacts.mjs

Command 2 — /propose-architecture

Objective. Tech-stack Q&A → architecture proposal + Proposed ADRs. Satellite: does not block plan or implement. Does not emit DDL, OpenAPI fields, or product code. ADRs stay Proposed — humans Accept them.

Primary: documentation-agent mode architecture. Recommended default presented to the operator: Java + Next.js.

flowchart TD O[orchestrator-agent] --> D["documentation-agent\nmode architecture"] D --> Q[open-questions-cataloger] Q --> A[tech-stack-advisor] A --> W[architecture-proposal-writer] W --> OUT["proposal + ADRs + logical-layers.mmd\naudit only — no harness row"] OUT --> NEXT["Next: /generate-brd or /plan-sprint"]

Outputs: docs/architecture/<date>-architecture-proposal.md, ADR files, questionnaire log, diagram. Copy suggested config.yaml bindings from the proposal by hand.

Command 3 — /plan-sprint

Objective. Accepted BRD → sprint backlog tagged implement-api / implement-ui. Gap analysis is an internal step, not a public command. Output is Proposed — Pending Approval.

Command 7 — /expand-test-coverage

Objective. Close remaining FR/BR design gaps: case bodies, matrix, completeness, BR coverage gate. Stops at Pending Approval. Does not generate scripts, run suites, or eval.

Objective. Generate executable tests from an Approved package, run them, persist results, analyze defects, suggest locator heals. Order: JUnit/IT → Vitest → Playwright.

flowchart TD O[orchestrator-agent] --> G{PASS + Approved?} G -->|no| REFUSE[Refuse] G -->|yes| STK["quality-agent\nrun-local-stack + verify-health"] STK --> SCR["Scripts by execution_layer\napi/IT → backend + spring-test-generator\nuat → frontend / playwright-codegen"] SCR --> EX["api-test-runner then ui-test-runner"] EX --> COV[coverage-analyzer] COV --> DEF[e2e-defect-analyzer] DEF --> HEAL["playwright-self-healer\nsuggestion only"] HEAL --> NEXT["Next: /run-eval"]

Self-heal never auto-merges. Applying a heal requires an explicit human request. If the API is down for E2E, record environment FAIL — do not skip journeys as pass.

Command 9 — /run-eval

Objective. Sole factory eval entry. Score coding, testing, and agent-output gaps against evals.rule_source. Emit completeness ledger and fix-queue. Silence (no case) is a finding, not a pass. Cannot waive P0/P1.

flowchart TD O[orchestrator-agent] --> Q[quality-agent] Q --> E["eval-agent\nincremental default"] E --> L[completeness-ledger + fix-queue] L --> AF{"auto_fix true\nopen?"} AF -->|yes| C["Invoke /close-eval-gaps"] C --> E AF -->|no| NEXT["Next: /review-changes"]

Incremental mode still includes always-on safety families L1-04, L1-05, L1-08, L1-09, L4-03. Missing ledger → review-changes will refuse.

Command 10 — /close-eval-gaps

Objective. Inner loop of run-eval. Walk fix-queue.json: skip waived / needs_human, delegate auto_fix: true to owning agents, re-run those case_paths only. Max 3 attempts per item.

flowchart TD O[orchestrator-agent] --> R[Read fix-queue.json] R --> CL[Classify items] CL -->|needs_human / waived| SKIP[Leave listed] CL -->|auto_fix true| OWN["Owning agent:\nbackend / frontend / api /\nquality / documentation"] OWN --> EV[eval-agent re-run those paths] EV -->|green| CLOSED[closed] EV -->|red| ATT{attempts under 3?} ATT -->|yes| OWN ATT -->|no| NH[needs_human] CLOSED --> LOG[fix-log + audits] NH --> LOG SKIP --> LOG LOG --> NEXT["Resume parent /run-eval"]

Command 11 — /review-changes

Objective. Read-only code, test, and security review of the slice. Does not run eval-agent. Missing completeness ledger → refuse.

flowchart TD O[orchestrator-agent] --> LEDGER{Completeness\nledger present?} LEDGER -->|no| REFUSE["Refuse → /run-eval"] LEDGER -->|yes| CR[code-review-agent] CR --> SEC[security-agent] SEC --> SR[security-reviewer] SR --> COV[coverage-analyzer] COV --> BR[br-coverage-validator read] BR --> OUT["artifacts/audit/date-review-changes.md"] OUT -->|Approve| NEXT["Next: /application-summary"] OUT -->|Block| FIX["Owning agents fix then re-review"]

P0/P1 remaining on the ledger forces Block. A family with zero cases is Block, not Approve. Reviewer must not mutate source.

Command 12 — /application-summary

Objective. Delivery summary with fresh metrics (not invented counts). Update harness via harness-updater.

flowchart TD O[orchestrator-agent] --> DOC["documentation-agent\nmode summary"] DOC --> W[application-summary-writer] W --> H[harness-updater] H --> A[audit-trail-writer] A --> OUT["artifacts/application-summary.html\noptional PDF"] OUT --> NEXT["Harness progress.md = Done"]

Metrics must come from the latest JaCoCo / npm / Playwright / BR-coverage artifacts collected this run.

Required contract shape

Primary (agent-template.md)

Goal · Must / Must NOT · Input checklist · Output checklist · Clarification protocol · Execution loop (max 3) · Check gates · Definition of Done · Audit and harness · Human gates · Delegates · Modes (optional)

Subagent (subagent-template.md)

Purpose · Parent · Must / Must NOT · Inputs · Outputs (structured IO + Confidence: high | medium | low + unresolved assumptions) · Failure modes · Quality gate · Ask-backs · Loop

Wire it — or the orchestrator will never call it

  1. Parent Delegates. Name the subagent on the primary’s ## Delegates list. A file in subagents/ is not enough.
  2. Command contract. If humans should trigger the work, add or edit a command: Use Agents: orchestrator-agent → <primary> and an ordered Delegate to Subagents chain. Commands never select a subagent as the slash-command primary.
  3. Mode (preferred over a new primary). If an existing primary already owns the domain, add ## Modes (example: backend-agent java / python) and branch the command’s phase table on config.
  4. scope.yaml. Grant write globs to the owning primary. Deny secrets, UI (for API agents), docs/harness/**, and docs/test-cases-br-coverage.md for implementers. Orchestrator stays artifacts/audit/** only.
  5. config.yaml. Add module roots, test commands, and health URLs the new agent will read. Placeholders remain a hard stop (rule 01).
  6. Rules and skills. Point the command’s Enforce Rules / Use Skills at the new files. Glob-scoped rules fire on generated paths.
  7. KIT-SCOPE.md + catalog-lock evals. Required when you add a public command or a primary. Factory meta-evals grade 12 primaries until you update them.
  8. Copilot allowlist. After a new primary: node tools/copilot/sync-agent-allowlists.mjs --root . --write. Prompt agent: stays orchestrator-agent.
  9. Run factory meta-evals (evals/factory/: catalog-lock, SoD, agent-contract-compliance, test-case-before-script) before teaching the new piece.
Hard rules for every new agent Do not invent business behavior, API fields, or UI copy. Return Open DQ / ASSUMPTION-<id> when sources are silent. Do not self-approve human gates. Do not add public /generate-backend, /generate-frontend, or /wire-* commands. Subagents return confidence to the parent; the parent rejects below-gate output (max 3).

13. Sample pattern — swap the API or UI stack

Use this when the lab or product is not Java 21 + Next.js. The kit will keep working only if you update command contracts, rules, skills, stack-conventions, config, scope, and all three IDE twins together. Do not add a 13th peer primary unless the work cannot live as a mode on backend-agent or frontend-agent. Kit catalog-lock evals grade 12 primaries.

Decision tree

flowchart TD Q1{"Changing API language\n(Java → Python / Kotlin / Go)?"} Q1 -->|yes| M1["Add a MODE on backend-agent\n+ language module-generator subagent\n+ test-generator subagent"] Q1 -->|no| Q2{"Changing UI framework\n(Next → other)?"} Q2 -->|yes| M2["Add a MODE on frontend-agent\n+ component-generator subagent"] Q2 -->|no| Q3{"New domain the 12 cannot own?"} Q3 -->|yes| P["New primary from agent-template.md\nUpdate catalog-lock evals\nTwin all three IDEs"] Q3 -->|no| S["New subagent or skill only"] M1 --> CMD["Edit /implement-api and /run-tests\nphase tables"] M2 --> CMD2["Edit /implement-ui and /run-tests"]

Standard procedure (do in this order)

  1. Write an ADR under docs/architecture/ using adr-template.md. Status Proposed until a human Accepts it. Cite the stack choice. Do not invent NFRs.
  2. Fill anatomy files from workshop/factory-anatomy/ for every new piece (subagent first, then rule, skill, then command edits).
  3. Add modes on the existing primary (## Modes on backend-agent / frontend-agent). Name them after the language (kotlin, python, go).
  4. Author stack-specific subagents that mirror the Java ones: <stack>-module-generator and <stack>-test-generator. Parent = backend-agent. Return structured IO + confidence. Must NOT invent columns or skip the BR coverage gate before scripts.
  5. Author or retarget a rule. Do not silently overwrite 03-backend-springboot if Java labs still run. Prefer 03-backend-kotlin.mdc with globs for the Kotlin module, and keep 03 for remaining Java paths — or replace 03 only when this drop-in is Kotlin-only.
  6. Author a coverage skill if JaCoCo does not apply (Kover, coverage.py, Go cover). Keep br-coverage — that skill is language-agnostic.
  7. Rewrite docs/architecture/stack-conventions.md for the new layering (packages, test runner, migration tool). Implement audits must record compliance against this file.
  8. Edit command contracts — see the tables below. This is the step people skip, and then orchestrator still spawns spring-module-generator.
  9. Bind config: modules.api (or modules.python / a new modules.kotlin key you also add to scope), evals.test_commands.api, local_stack.api_health_url.
  10. Update scope.yaml write globs for backend-agent. Deny UI and harness. Keep docs/test-cases-br-coverage.md denied for implementers.
  11. Twin Cursor, Claude, and Copilot in the same change. Copilot primaries need YAML frontmatter; regenerate allowlists with node tools/copilot/sync-agent-allowlists.mjs --root . --write when adding a primary.
  12. Run factory meta-evals under evals/factory/ (catalog-lock, SoD, agent-contract-compliance, test-case-before-script).
  13. Update KIT-SCOPE.md and this playbook so the next audience does not think Java is mandatory.
